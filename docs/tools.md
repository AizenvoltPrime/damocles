# Tools

This page covers the optional tool groups that are not covered elsewhere (web tools, image generation, and GitHub and GitLab), how deferred tool loading keeps unused tools out of the prompt, and the Tools panel.

The browser, Compass and MCP tools have their own pages: [Browser](browser.md), [Compass](compass.md) and [MCP servers](mcp.md).

## Order of tool calls in one reply

The agent can ask for several tool calls in one reply, and they usually run at the same time. When a reply holds an `Edit` or a `write`, all its calls run one after another in the order the agent wrote them, so a `read` or a test command after an edit sees the edited file. That includes foreground `Agent` calls: subagents started in the same reply as an `Edit` or `write` run one after another, not side by side.

A `read` never sees a file half written by Damocles' own file tools. For an existing file this holds against `Edit` and `write`: a `read` waits in a per-file queue until an `Edit` or `write` of that file in the same Damocles engine process has finished; `GenerateImage` creates its file atomically, so any reader sees no file or the whole image. It does not hold against MCP tools or shell commands: a shell command such as `cat` can still see a file an `Edit` or `write` is writing, and a `read` can see a file an MCP tool or a shell command is writing.

## Web tools

The web tools are on by default; turn them off in Settings › Tools & integrations or via `damocles.pi.webSearch.enabled`. The toggle takes effect on the next turn with no install or reload.

Five native, **key-free** read-only tools:

- **WebSearch**: an answer with cited sources, with optional category / domain / publish-date filters via Exa's advanced search
- **WebFetch**: read a web page or PDF as markdown, with `raw` / `maxChars` / `includeLinks` / `includeImages` controls
- **CodeSearch**: search public source code and docs
- **FeedRead**: read an RSS 2.0 or Atom feed as markdown
- **YouTubeTranscript**: best-effort video transcript when captions are available, though YouTube may block it

WebSearch and CodeSearch are backed by Exa's free endpoint; no API key or config is required. WebFetch extracts HTML via Readability, reads PDFs inline, fetches a GitHub `blob` or `raw` page from `raw.githubusercontent.com`, and falls back to the `r.jina.ai` reader for JavaScript-heavy pages. Every outbound fetch is validated to block internal/loopback/cloud-metadata addresses.

WebFetch never contacts a host that a deny or ask `WebFetch(domain:<host>)` rule matches on a step it takes by itself ([Permissions](permissions.md)): with `raw.githubusercontent.com` matched it fetches the GitHub page as named, with `r.jina.ai` matched it returns the direct result without the reader, and a redirect to a matched host other than the URL's own stops, with the result naming the redirect's URL, which the agent can fetch as a call of its own that the rules judge. Allow rules change none of this, and ImportAsset's URL fetch stops at such a redirect the same way.

All five are read-only, available in plan mode and inherited by `tools: *` subagents. They start **deferred**: their schemas are not in the prompt until the agent loads them with `ToolSearch`, so a turn that never searches the web costs nothing for them. See [Deferred tool loading](#deferred-tool-loading).

## Image generation

An opt-in `GenerateImage` tool (`damocles.imageGeneration.enabled`, off by default and settable only in user settings) creates a new PNG, JPEG or WebP file at the path you approve from a text prompt. It uses an OpenRouter image model you pick in Settings (`damocles.imageGeneration.model`, also user settings only) and your OpenRouter key or sign-in, which you set under OpenRouter in Settings › Models & accounts. Only models whose cost pi can track are offered. The agent loads it with ToolSearch when it needs it.

It goes through the same permission gate as Write: it asks with the path, the prompt and the model in Default mode, runs without asking in Accept Edits, is blocked in Plan mode, never overwrites a file, and a rewind removes the image. The image appears at its path only once it is complete: any program reading the path sees no file or the whole image, never part of one. The cost OpenRouter billed counts in the status bar, the budget and `/stats`, under the image model. The generated image shows in the tool's overlay. Subagents and team agents do not get the tool.

## GitHub and GitLab (desktop)

With a GitHub or GitLab account signed in (Settings › Models & accounts › Git hosting, see [Git hosting accounts](git-hosting.md)), the agent can read and act on the chat project's repository through that account, instead of `gh`, `glab` or `curl` with git credentials:

| Tool | What it does |
| --- | --- |
| ForgePipelines | Lists the newest CI pipelines (GitHub: workflow runs) of the current branch, or of `branch` |
| ForgeJobs | Lists a pipeline's jobs, the latest attempt of each, up to 10 pages, saying when the list is cut |
| ForgeJobLog | Reads the last lines of a job's log, 200 at most, colors removed; `section` keeps only the sections whose name holds it. A GitHub job still running answers that its log is published when the job completes |
| ForgeMergeRequest, ForgeMergeRequests | Read one merge request (GitHub: pull request) with its latest comments (on GitHub its conversation comments, review comments not included), or list them |
| ForgeIssue, ForgeIssues | Read one issue with its latest comments, or list them |
| ForgeJobAction | Retries or cancels a job (on GitHub, cancel stops the whole workflow run, and a retry answers the new attempt, or that the rerun was requested while GitHub does not list it yet); asks first |
| ForgeOpenMergeRequest | Opens a merge or pull request from a pushed branch; asks first. When the remote pushes to your fork on the same server, it opens one from the fork into the repository the remote fetches |
| ForgeComment | Comments on a merge request, pull request or issue; asks first |

- The group is called `forge`, and the agent loads it with ToolSearch when it needs it. It can be loaded only while an account exists, never in a design chat or by the agents a design chat starts. `damocles.desktop.forge.agentTools` (on by default) switches it off. The Explore and Plan subagents get the read tools; team reviewers and read-only agents get no writes. A subagent or team member started while no account exists has none of the tools.
- The tools always act on the chat's own repository: its git remotes give the server and the project, and the project's account answers. A remote's fetch address names the project; when that address is on no server Damocles knows, its push address does.
- A write runs only on what its card showed: when the repository, the account, a branch or the text to send changed after you approved it, nothing is sent and the agent is told to call the tool again. A tool takes at most a remote name (`origin`, `upstream`), numbers and text, never a server address. With `damocles.desktop.forge.agentReadAnyRepository` on (off by default), the read tools may name another repository on the same server; the writes never can.
- What the server returns is treated as data: secrets in it are redacted, your live tokens masked, hidden characters removed, and the text is marked as coming from the server. A result over 20 KB is cut; in a chat on this computer the full text is in a temporary file the agent can read.
- When the project has no account on its server, the call fails and the chat shows a notice with Choose account. When a GitHub organization requires single sign-on, or has not approved Damocles, the notice offers to authorize Damocles or to request approval.
- In a chat on a remote host the tools run on your computer with your accounts, only for that host's projects, and only text comes back: no token reaches the host. They are unavailable while your computer is not connected or while the group is off on it.

## Themes (desktop)

In a main chat of the desktop app, the agent can read and change this computer's app look, also from a chat on a remote host. A change reaches the window only through a card you answer or the keep-changes banner:

| Tool | What it does |
| --- | --- |
| ThemeRead | Reads what shows and why (`about: 'current'`), the installed themes (`installed`), one theme's colors, style and contrast issues (`theme`), the saved schedule (`schedule`, a rule that never shows because a later rule starts at the same time on each of its days is marked `shadowed`), or the chat's project's own look (`project`), as JSON of at most 40,000 characters. `preview: true` adds one drawn preview (a 1280x800 picture of the theme's miniature with sample content only, nothing of yours); `screenshot: true` adds a screenshot of the window after you allow it on a card that shows it first; the card closes unanswered after 10 minutes, or as soon as the window lets go of the screenshot to hold newer ones, and the agent is told which |
| ThemeSet | Shows an installed theme as it is for one look (a theme id with nothing to change: no theme is made or saved, and a built-in is not copied), or creates or edits a theme (8 main colors per look, advanced tokens, installed fonts, line spacing, corners, density, chat column, wallpaper sets and their cycle, still or moving wallpapers from a file, a URL or an attached one, still ones also generated, the window arrangement; a moving file that flashes is blocked until the user allows it in the theme editor or on the install card, which the agent cannot) as a draft and proposes it, or stages the draft with no card. `undo: true` reverts this chat's own newest theme change, `wallpapersOff: true` proposes turning Show wallpapers off, and `install: { url }` installs a theme from an https link after the install card |
| ThemeSchedule | Proposes the theme schedule: rules by days and start time in this computer's local time, each naming a theme and a look (dark, light, or auto, which follows the computer). Once applied, the rule whose start is the latest at or before now decides the look; turning the schedule on makes a System mode the kind on screen. A call changes only what it names: without `enabled` the schedule stays on or off as it was (a first schedule needs `enabled: true`), and without `rules` the saved rules stay. It never changes the window arrangement |

- The group is called `theme`, and the agent loads it with ToolSearch when it needs it. Only a main chat has it: a design chat, the agents a chat starts and VS Code have none of the tools. A main chat on a remote host has them while the computer its turn came from is attached, runs a Damocles that relays them and has the group on; they change that computer's app, never the host, whose Damocles keeps no theme, and the Tools panel says when that computer's Damocles is closed or too old. `damocles.desktop.themes.agentTools` (on by default) switches the group off, and each tool has its own switch in the Tools panel.
- **Theme changes from the agent** (Settings › Appearance, `damocles.desktop.themes.applyMode`, yours alone): *Preview first* (default) shows a card in the chat with Apply, Discard and Change… (your note goes back to the agent, which keeps working on the same draft), and Show in window to paint the proposal on the window until you stop it. While a Windows contrast theme is on, or the run shows the Damocles theme (safe start), the window cannot paint a proposal: Show in window stays off and the card says why. *Apply on the fly* applies at once and shows a banner under the title bar for 15 seconds: Keep, or Revert now (also what happens when the time runs out). Any later theme change while the banner counts, by the same chat, another chat or you, joins it and restarts the 15 seconds, and Revert now or the timeout brings back the look from before the first change; once the changes come from more than one chat, or from you and a chat, the banner names no single chat. In Plan mode the card shows instead. Either way each change is one entry of the theme history under whoever made it, which Undo theme change reverses: a chat's later change while its own entry is the newest folds into that entry, and every other change during the countdown is an entry of its own, so Undo and each chat's `undo` still take back one change at a time.
- When a theme the card proposes changed after the proposal (another chat or you saved it meanwhile), the card says so and offers Discard only. A chat keeps at most 3 drafts and Damocles at most 20; they live in `~/.damocles/themes/drafts` and go when you discard, when the turn stops, when applying fails, when the chat closes and when Damocles starts. A turn you stop applies nothing that was not applied yet, on the fly included, and the result tells the agent what Apply did: whether the theme was picked or only saved, whether the schedule is on, or that nothing changed because it was already set that way.
- `undo` reverts only the chat's own newest change, and only when nothing changed the same theme or setting after it; otherwise it is refused and the agent is told which change came later.
- Names, descriptions, authors and licenses of themes that came from outside this computer reach the agent only inside an `untrusted` field, on one line, without control or direction-changing characters and cut short, and the group's line tells the agent they are data, not instructions. ThemeSet sets a look's wallpapers (`wallpapers`: sets of one image per panel or one image across panels, each image the sha256 of one the theme has, which ThemeRead lists, or the name of the call's `asset`), its `surfaceOpacity` and its 8 colors from a wallpaper's proposed palette (`paletteFromWallpaper`); `asset` brings in one image per call (a still PNG, JPEG, WebP or AVIF of at most 20 MB, or a moving GIF, animated WebP or PNG, MP4 or WebM of at most 40 MB; a generation makes stills only), from one source in `asset.from`: `{ file }`, a path on the chat's machine as Read takes it; `{ url }`, an https URL, fetched only while Web search is on and with no redirect followed (the agent calls again with the address it was sent to), stopped after 30 seconds without data or 10 minutes in all, its type taken from the answer and the bytes, never from the URL's path; `{ generate: { prompt, aspect? } }`, made with your image generation model (Settings, Image generation) and billed to your OpenRouter key, the aspect (`16:9`, `16:10`, `21:9`, `3:2`, `4:3`, `1:1`, `9:16`) added to the prompt; or `{ attachment: n }`, the n-th image you attached in the chat, counted over the whole chat whatever a compaction took out of the context. An `asset` that no field of the same call uses (`wallpapers`, `paletteFromWallpaper`, `characters`, or `projectLook.wallpaper` with `target: 'project'`) is refused before its source is read or generated, each result names the sha256 of the image or sprite it stored, and a wallpaper image no look names any more leaves the theme. Each source is judged before anything is read: a file by your `Read` rules, a URL by your `WebFetch` rules, a generation as GenerateImage is (it asks in Default and Plan mode, runs in Accept Edits and YOLO); see [Theme tools in docs/permissions.md](permissions.md#theme-tools). The bytes must be the type the file's name, the URL's answer or the image's declared type says. The image goes straight into the theme's own files under `~/.damocles/themes/blobs`; a generated or downloaded image never leaves a file in your project. `stage: true` builds or updates a draft without a card and returns its draft id and the drawn preview, so the agent can take several steps before it proposes one card. `wallpapersOff: true`, alone, proposes turning your Show wallpapers setting off through the same card or banner as any change, as one history entry that Undo reverses; only you turn it on again, and Toggle Wallpapers (`Ctrl+Alt+Shift+W`, `Cmd+Alt+Shift+W` on macOS) stops them at once without the agent. `layout: 'current'` saves this computer's window arrangement in the theme (where the chat, editor and terminal sit and their sizes, the sidebar's width, its section order and which sections are collapsed), and `layout: 'none'` removes the theme's arrangement. Applying a draft that picks a theme puts the theme's arrangement in place exactly as your own pick does, when it came from this computer or you turned on Use this theme's window arrangement at install (a copy of a theme you did not turn it on for keeps it off), and its card says so, in the same history entry, so Undo and the chat's `undo` give the window back its arrangement; a schedule, a project switch and an install never apply one. In a chat on a remote host `current` is the arrangement of the computer the turn came from, which that computer reads; the host never reads or guesses it. `install: { url }`, alone, installs a theme from an https link (a `.damocles-theme`, a VS Code theme `.json` or `.vsix`, a base16 or base24 `.yaml` or `.yml`, a KDE `.colors` or `kdeglobals`, a qt5ct or qt6ct `.conf` or a GTK `.css`): it is judged as a `WebFetch` of that URL and runs only while Web search is on, the file is downloaded and checked, and the install card in the chat lists what it holds, with Install or Cancel, Keep both or Replace on a name clash and Use this theme's window arrangement (off by default). The card shows each moving wallpaper's flash check as it runs; a file that flashes more than three times a second shows Blocked, the seizure warning and Allow flashing for this file, which only you press and which allows that file on this computer alone. Installing never shows the theme. From a chat on a remote host the computer the turn came from downloads and installs the file, and only while its own Web search is on too; the card on another computer attached to the host names that computer and offers Cancel only. `asset.from.pixels` (`{ palette, frames, fps? }`: up to 16 `#rrggbb` colors, up to 12 frames of the same 1 to 32 rows of 1 to 32 pixels, one character a pixel, `.` clear and `0` to `f` a palette color, 4 frames a second by default) draws a character sprite, which Damocles turns into one sprite-strip SVG with square pixels, checks like any sprite (flashing included) and stores; it reads nothing and asks nothing. `characters` sets the theme's set of project characters (`{ name?, characters: [{ name, alt?, idle, running?, waiting? }] }`, each state the name of the call's pixel asset or the sha256 of a sprite the theme has, which the result and ThemeRead give), or `null` removes it; one sprite per call, so the agent stages a draft and adds sprites over several calls. `target: 'project'` with `projectLook` sets the look of the chat's own project (a chat worktree's is its project's) on this computer, through the same card or banner, and changes no theme: `{ mode: 'none' }` turns it off, `{ mode: 'full', theme, look? }` gives the project an installed theme of its own (`dark`, `light` or `auto`, the default), and `{ mode: 'touches', accent?, wallpaper?, characterSet? }` changes what it names on top of the touches the project has (`null` removes one): an accent kept readable in each look, one wallpaper set whose images are the call's `asset` or the sha256 of one the project's look has, and the id of a theme whose characters it shows. Only `asset` may come with it. ThemeRead `about: 'project'` reads the chat's project's look, and with `screenshot: true` adds the screenshot you allow and with `preview: true` a drawn preview of the project's own theme, or of the shown theme with the project's touches.

## Deferred tool loading

The browser, Compass, web, GitHub and GitLab, theme, and MCP tools, and the MCP resource tools (group `mcp_resources`), start registered but **inactive**, so their schemas are not in the prompt on turn one. A conversation that never touches them never pays for them. The resource tools are the one exception to deferral: when a resource server is set to Always loaded, all three are declared from the first turn.

The agent loads a group on demand with the always-active `ToolSearch` tool, and the tools are callable from its next step. The menu it reads is built from live workspace configuration, so a subsystem you disable mid-session drops out of it rather than staying advertised.

What this saves depends on your provider: a tool never loaded always costs nothing, and on Anthropic *loading* a group mid-conversation still reads the cached system prompt and initial tools, so only the new schemas and the messages are written to the cache again. Subagents and team agents resolve through the same deferral, so no agent kind is a hole. `/context` shows the split; see [Context stats](chat.md#context-stats).

## Tools panel

A status panel lists every agent tool grouped by subsystem (core, memory, compass, browser, web, image, GitHub and GitLab and Themes on desktop, design), each with a per-tool enable switch and a per-subsystem master switch. Core built-ins are locked on; the other groups' tools toggle. The GitHub and GitLab group shows as unavailable until an account is signed in; in a chat on a remote host, while Damocles is still reading the accounts of your computer, it says so instead. It opens from the Tools button in the chat header (in its More menu when the panel is narrow).
